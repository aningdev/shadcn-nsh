Editor

An editor on the field's well, with line numbers, diagnostics and a find bar.

NSH

Installation

Usage

Every prop of nsh/base Editor passes through: the text (value / defaultValue, onChange), the language and its highlighting, folding, soft wrap, search, the editing keys and the diagnostics. The shell adds the look (editorClasses) and the surface (editorFrame()).

Examples

Languages

language takes a name, an extension or a file name; the editor highlights it and follows its editing rules (comments, brackets, indentation).

Diagnostics

Ranges the app marks, carried through edits until it sets new ones: an error is underlined in the theme's destructive, a warning in warn, information in info, a hint in muted-foreground.

Find and replace

search is what the editor finds and highlights; onSearchChange says what it found — how many matches, which of them the selection is on, or why a pattern is not a regular expression. The editor never sets the search itself (EditorRef replaces a match, it does not find one), so the bar that edits it is a part: EditorFindBar takes the editor's ref, the same object the app hands the editor's search, and the result the editor reported. What is typed into the bar goes back through onSearchChange; its buttons run the editor's own findNext, findPrevious, replace and replaceAll (and the bar says how many a Replace all rewrote for a moment).

Where the bar is and whether it is open are the app's: it sits beside the editor in the same View rather than inside it, since a part cannot leave the tree. The keys are the app's too — Escape and mod+f belong to its keymap, as a part that captured them would take them from the editor while the bar is closed. Because the search is one object, a query the app sets — from onFindWithSelection, or from a keybinding — reads in the bar, and the bar's edits move the editor's matches as it types.

Parts

classes goes over editorClasses part by part (an app's classes come after ours; null drops ours), and style over editorFrame(). The font is set with fontFamily, fontSize and lineHeight, which the editor measures its rows in.

Hover and quick fixes

onHover reports where the pointer rests: the character, the word it is in, the word's box on the page (pageBounds, what a popup is placed against) and the diagnostics there; onHoverEnd says it left. The app answers with an Overlay anchored to that box, so the card follows the word as the text scrolls and flips below it where there is no room. A card that carries buttons is kept alive while the pointer is over it — onMouseEnter / onMouseLeave on the card, a timer that closes it a moment after the pointer leaves — or it vanishes under the pointer on the way to them. A fix rewrites the file, which the app owns (value / onChange).

Controlled text

Pass value and set it again in onChange; the app owns the file, as a formatter's output or a loaded file replaces it.
