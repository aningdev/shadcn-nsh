# WinUI 3 Theme (`winui`)

WinUI 3 (**Windows 11**, static baseline with `#0078D4` default Windows accent) for `shadcn-nsh`. Implemented under the two-file design-semantics standard (`theme.json` + `semantics.json` with `{token}` finish references) and selected automatically by `nativeTheme()` when running on Windows.

> [!NOTE]
> **Basis & approximations:**
>
> - **Baseline sources:** Windows App SDK **`v2.7.0`**, `microsoft/microsoft-ui-xaml` tag **`winui3/release/2.7.0`** (`1b5b1a0ccc05ce5c8b5931dc303666975b57f498`), `microsoft/WinUI-Gallery` (`6de91fec`), and `MicrosoftDocs/windows-dev-docs` (`docs` branch).
> - **OS runtime values (unverifiable in static XAML):** `microsoft-ui-xaml` binds `SystemAccentColor*` dynamically via `Windows.UI.ViewManagement.UISettings`; the default Windows 11 blue ramp (`#0078D4` base, `#005FB8` Dark1, `#003E92` Dark2, `#60CDFF` Light2, `#99EBFF` Light3) reflects OS runtime `UISettings` defaults, and arbitrary host accents derive their 6 tiers in OKLCH (`scripts/theme/winui.ts`).
> - **Approximations:** Translucent `#AARRGGBB` WinUI brushes are composited opaque onto `SolidBackgroundFillColorBase` (`#F3F3F3` light / `#202020` dark), except `brand-edge` which composites `ControlStrokeColorOnAccentSecondary` onto `AccentFillColorDefault` (`primary`). `glass` approximates Light `TintColor` `#FCFCFC` via `{popover}` (`#F9F9F9` fallback) at WinUI's per-appearance `TintLuminosityOpacity` (`0.85` light / `0.96` dark). CSS elevation shadows (`shadow2/8/16/32/128`) are derived from the two-layer ambient + key formula at WinUI's layering depths to approximate dynamic 3D `ThemeShadow`. `state.disabled.fill: true` switches split disabled controls (`Button`, `Toggle`, `IconButton`, `RoundButton`, `SplitButton`) to `finish.disabled` (`ControlFillColorDisabled`) + `finish.disabled.foreground` (`TextFillColorDisabled`, `content: 0.36`; non-split controls use the `0.36` opacity fallback, whereas WinUI `AccentFillColorDisabled` is `0.216` L / `0.157` D and `TitleBarDeactivatedOpacity` is `0.5`).
> - **Verification environment caveat:** All screenshots (`port:render`, `port:render:theme`, `port:sheet`) were captured on macOS / headless Chromium web rather than on a Windows 11 host. Native Windows backdrop blur (`material.windows.backdrop: "blur"`), `Segoe UI Variable` / `Consolas` font rasterization on Windows, and touch-screen sizing branches (`platform.desktop === false`) are verified via unit and gallery tests (`bun test ./scripts/theme`, `bun run test:gallery`) rather than on Windows hardware.

> - **Input tiers:** The pointer tier is WinUI 3's only published density (Standard); the touch tier is this library's own, adding `8` to each pointer height (`32 / 40 / 48` control heights) to meet Windows' touch-target guidance of ~`7.5mm` / `40×40` effective pixels ([`guidelines-for-targeting`](https://learn.microsoft.com/windows/apps/design/input/guidelines-for-targeting)).
> - **Popup list rows:** `dimension.size.item` is `inset: 4` and `pad: 11` on both tiers, as `MenuFlyoutPresenter`'s `4px` padding and `MenuFlyoutItem`'s `11px` horizontal padding (`MenuFlyout_themeresources.xaml`); the highlight's corners stay concentric with the `8px` flyout.

## Component Comparison (WinUI 3)

Every `registry:ui` component in `registry.json` (83 total) audited against official WinUI 3 specifications (`winui3/release/2.7.0`, `windows-dev-docs`, and `microsoft/WinUI-Gallery`):

- **matches**: Theme tokens, finishes, typography, indicators, focus rings, and motion align within the shared component architecture.
- **Class A (fixed)**: Theme colour/mapping or demo parity issue resolved for `winui` while keeping `default`, `shadcn`, `solid-glass`, `apple`, and `material` pixel-identical.
- **Class B**: Intentional shared-shell structural gap where the component uses a single cross-theme geometry or omits WinUI-specific sub-parts to preserve registry uniformity across all themes. Tracked in [#235](https://github.com/aningdev/shadcn-nsh/issues/235).
- **Class C**: Component belongs to NSH's desktop, terminal, code, chat, or layout utility layer with no official WinUI 3 specification; styled consistently using WinUI surface, border, typography, and motion tokens.
