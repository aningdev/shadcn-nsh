# Material Theme (`material`)

Material Design 3 (**M3 Expressive**, Android baseline palette) for `shadcn-nsh`. Implemented under the two-file design-semantics standard (`theme.json` + `semantics.json` with `{token}` finish references) and selected automatically by `nativeTheme()` when running on Android.

> [!NOTE]
> **Verification environment caveat:** All screenshots (`port:render`, `port:render:theme`, `port:sheet`) were captured on macOS / headless Chromium web rather than on a physical Android device or Android emulator. Visual values, layout, and web shadows/state layers match headless renders; native Android elevation (`material.android.elevation`), native platform ripples (`android={{ ripple }}`), and touch-screen sizing branches (`platform.desktop === false`) are verified via unit and gallery tests (`bun test ./scripts/theme`, `bun run test:gallery`) rather than on Android hardware.

## Component Comparison (`m3.material.io`)

Every `registry:ui` component in `registry.json` (83 total) audited against official Material 3 / M3 Expressive guidelines:

- **matches**: Theme tokens, tonal finishes, typography, indicators, and focus/state rules apply cleanly within the shared component architecture.
- **Class A (fixed)**: Theme responsiveness or contrast issue in shared UI code that was fixed for `material` while keeping `default`, `shadcn`, `solid-glass`, and `apple` pixel-identical.
- **Class B**: Intentional shared-shell structural gap where the component uses a single cross-theme geometry or omits M3-specific sub-parts to preserve registry uniformity across all themes. Tracked in [#233](https://github.com/aningdev/shadcn-nsh/issues/233).
- **Class C**: Component belongs to NSH's desktop, terminal, code, chat, or layout utility layer with no official Material 3 specification; styled consistently using M3 surface, border, typography, and motion tokens.
