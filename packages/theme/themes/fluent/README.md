# Fluent Theme (`fluent`)

Fluent 2 (**Windows 11 / WinUI 3**, static baseline with `#0078D4` default Windows accent) for `shadcn-nsh`. Implemented under the two-file design-semantics standard (`theme.json` + `semantics.json` with `{token}` finish references) and selected automatically by `nativeTheme()` when running on Windows.

> [!NOTE]
> **Verification environment caveat:** All screenshots (`port:render`, `port:render:theme`, `port:sheet`) were captured on macOS / headless Chromium web rather than on a Windows 11 host. Visual values, layout, and web shadows/state swaps match headless renders; native Windows backdrop blur (`material.windows.backdrop: "blur"`), `Segoe UI Variable` / `Cascadia Mono` font rendering on Windows, and touch-screen sizing branches (`platform.desktop === false`) are verified via unit and gallery tests (`bun test ./scripts/theme`, `bun run test:gallery`) rather than on Windows hardware.

## Component Comparison (WinUI 3 / Fluent 2)

Every `registry:ui` component in `registry.json` (83 total) audited against official Fluent 2 / WinUI 3 specifications (`windows-dev-docs` & `microsoft-ui-xaml` `winui3/release/2.7.0`):

- **matches**: Theme tokens, finishes, typography, indicators, focus rings, and motion align within the shared component architecture.
- **Class A (fixed)**: Theme colour/mapping or demo parity issue resolved for `fluent` while keeping `default`, `shadcn`, `solid-glass`, `apple`, and `material` pixel-identical.
- **Class B**: Intentional shared-shell structural gap where the component uses a single cross-theme geometry or omits WinUI-specific sub-parts to preserve registry uniformity across all themes.
- **Class C**: Component belongs to NSH's desktop, terminal, code, chat, or layout utility layer with no official Fluent 2 / WinUI 3 specification; styled consistently using Fluent surface, border, typography, and motion tokens.
