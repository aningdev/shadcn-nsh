Foundations

Behavior from NSH, appearance from a theme, and one source installed two ways.

Native behavior, styled shells

Interaction, keyboard navigation, and accessibility come from nsh/base. The shell adapts density and input across iOS, Android, macOS, Windows, Linux, the web, and the terminal.

3-layer data-driven themes

Tokens in theme.json, a ThemeSpec for surfaces, controls, metrics, and motion, then native materials and WGSL shaders. nativeTheme() follows the platform. defineTheme() derives your own.

FAQ

Is this an official NSH project?+

No, it is a community project. Behavior, keyboard navigation, and accessibility come from NSH's own nsh/base, unchanged. The look starts from NSH's official example UI and is owned and maintained here.

How does it relate to shadcn/ui? Can I use it in a React web app?+

It follows shadcn/ui's model — a registry, a CLI, one file per component, and parts named Trigger, Content, Item — but the components draw NSH native views, not the DOM, so they don't run in a React DOM app. An NSH app reaches the browser through NSH's web target, which is how every demo on this site runs.

TSX nshm or the copy-into-app CLI — which do I use?+

Both ship the same source, and neither adds a third-party runtime dependency. nsh add github:aningdev/shadcn-nsh resolves the TSX nshm module. There is no package.json entry and no node_modules for this library; import from shadcn-nsh/<name> and switch themes with selectTheme. The CLI (npx shadcn-nsh@latest init, then add <name>) copies the files into the app. After that they are yours: diff shows what changed, and add <name> --overwrite writes the registry's version over yours. Use nshm when you want the module as it ships. Use the CLI when you want to edit the shell or the look.

Which platforms does it run on?+

Wherever NSH does: iOS, Android, macOS, Windows, Linux, the web, and the terminal. Each component adapts its density and controls to a touch screen, a pointer, and a keyboard.

Which NSH version do I need?+

Each release tracks one NSH CLI version. The compatibility table lists them.

Do the built-in themes clone native controls 1:1?+

No. Each theme distills the colors, radii, surfaces, and motion of its design system onto the same nsh/base controls. It does not replicate every platform widget. The mapping and the deliberate trade-offs are on each theme page.

Can I make my own theme?+

Yes. defineTheme() takes a built-in theme's spec and the fields you change; selectTheme() applies it while the app runs. See Customizing.

Does it work with AI coding assistants?+

Every docs page is also Markdown: add .md to its URL. /llms.txt indexes them and /llms-full.txt holds them all in one file.

What is the license?+

MIT. The copied files are yours, with no runtime dependency on this project.
