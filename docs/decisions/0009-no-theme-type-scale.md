# 0009 主题不定制字体与字号

- 日期：2026-11-24
- 状态：已采纳（2026-11-24）
- 修订：[0007](0007-theme-customization-scope.md) 第 1 条“全局风格”的“字体”一行
- 规范：NSH 文档 [字体 · 应用的默认字体](https://nsh.dev/zh-CN/docs/fonts#应用的默认字体)、[文字 · 系统字号](https://nsh.dev/zh-CN/docs/text#系统字号)

## 背景

0007 把“字体：字族、字阶、字重”列为每套主题都写的全局风格。但 NSH 已经替两件事做了主：

- **字体族归应用。** 应用在 `nsh.json` 的主题里设 `font-sans` / `font-mono`，没设自己字体族的文字都用它；不设时就是系统字体（iOS 的 San Francisco、Android 的 Roboto）。
- **字号跟随用户。** 文字默认按用户的系统字号设置缩放（iOS 的动态字体、Android 的字体大小），`fontScale()` 随设置变化。

现状：六套主题里五套的 `font.family` 是 `system-ui` / `monospace`，只有 winui 写了 Segoe 与 Consolas；apple、material、winui 各写了一套字阶（指针、touch 两档）。

## 决定

- **字体族不进主题。** 删掉各主题的 `font.family`；组件不设 `fontFamily`（等宽处用 `monospace` 这类通用族），继承应用的 `font-sans` / `font-mono`。想用 Segoe、Inter 的是应用，在 `nsh.json` 里设。
- **字号不按主题定制。** 本库只有一套字阶（基础字阶，`default` 的值），所有主题共用；用户的系统字号在它之上缩放。apple、material、winui 的字阶删掉，与原生的差别按 0004 第 2 条记进 `native-themes.md` 第 3.6 节。行高随字阶走，同样不按主题定制。
- **字重留在全局风格。** 字重不受系统字号影响，按钮、标签的字重是平台能一眼认出的差别（如 #353）。
- **缩放上限归组件。** 需要限制放大的地方（标签页、徽标这类定高的控件）在组件里设 `maxFontSizeMultiplier`，不进主题；不关闭缩放。

0007 第 1 条“字体”一行因此读作：“字重”。

## 理由

- **NSH 已经有主人。** 字体族在应用的主题里、字号在用户的设置里；主题再写一层，要么与应用的 `font-sans` 打架，要么被用户的缩放抵消。
- **平台字阶的差别很小，代价不小。** 17 pt 与 14 pt 正文的差别在用户调大字号后就淹没了；三套字阶 × 两档密度要维护、要渲染比对。
- **字重是例外。** 它不随用户设置变，又是平台外观的一部分，留下成本很低。

## 不采纳的方案

- **保留平台字阶，只删字体族。** 字阶仍是每遇到一个平台就要讨论的一组数，正是 0007 想关掉的口子。
- **连字重也删。** 按钮标签的字重（#353）是关键组件外观的一部分，删掉会把刚修好的差别再带回来。
- **主题里设 `allowFontScaling: false` 保持平台字阶精确。** 大字号是很多人依赖的辅助功能，NSH 文档也建议限制比例而不是关闭。
