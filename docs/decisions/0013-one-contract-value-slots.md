# 0013 一套契约、按主题配值：控件形态改为数值槽

- 日期：2026-11-25
- 状态：已采纳（2026-11-25）
- 取代：[0007](0007-theme-customization-scope.md) 第 2 条“配方只能经四个控件维度表达”与第 3 条中保留 `field`、`choice`、`track`、`handle` 四个枚举的部分；[0004](0004-theme-contract-freeze.md) 第 1、3 条对这一次重构的限制（其余照旧：不为一套主题加键、组件里不写主题分支）

## 背景

目标（2026-11-25）：同一份公共契约，按主题配不同的值，表达 apple、material、winui 与 nsh-gallery 在 0007 第 2 条关键组件与全局样式（边、阴影、圆角、尺寸、焦点、状态层）上的差别。

现状不是这样。契约的控件维度是**形态枚举**（`field: box | underline | box-underline`、`choice: well | outline | inset`、`track: sunk | tint | hairline`、`handle: circle | ring`、`corners.button: full | radius`、`disabled.fill: boolean`），每个取值对应一个平台；数值写在组件库里（`packages/ui/lib/look.ts` 的四张表、`switch.tsx` 的 `winuiSwitch` / `materialSwitch`）。结果是：

- 枚举就是换了名字的主题分支：`switch.tsx` 用 `handle === "ring"` 认出 winui、用 `track === "tint"` 认出 material。
- 平台的数值不在主题里：apple 的椭圆旋钮、20×16 滑块、4pt 轨道都写不进去，只能再加一个枚举值，也就是再加一个平台分支。
- 同一类差别有多种写法：选中行“有边 / 只有填充”、日历今天“墨色 / 圆底”、禁用“变暗 / 换填充”各自一个开关。

## 决定

1. **形态枚举改为数值槽。** 每个关键组件组在契约里有一组固定的槽：填充、边（宽度与颜色，可按边分）、圆角、阴影、尺寸、状态。主题只给值；“形态”的差别由退化值表达：
   - 边宽 0 或边色等于填充 → 只有填充（例：选中行有边 / 无边）；
   - 侧边与上边宽 0 → 下划线输入框；
   - 旋钮宽等于高 → 圆，不等 → 椭圆；圆角等于高度一半 → 胶囊；
   - 阴影 `none` → 平面；内点直径 0 → 无内点（winui 的环形滑块是“外圈 + 内点”的数值）。
2. **组件只有一种画法。** 组件读槽、按值画，不认主题、不认形态名；`look.ts` 的表与 `switch.tsx` 的平台配方搬进各主题的 `semantics`（DTCG 源码，带出处，0012）。
3. **槽集合对所有主题相同。** 新增一个槽必须对所有主题都有意义，且 nsh-gallery 有值；为一套主题新增槽仍然禁止（0004 第 3 条不变）。
4. **表达不了的仍降级。** 某平台的样子用这组槽表达不了，记 `native-themes.md` 第 3.6 节，不加槽、不加分支。
5. **槽表是规范。** 每组槽、各主题的值与出处列在 [`theme-slots.md`](../specs/theme-slots.md) 的矩阵里；`check:theme` 校验每套主题每个槽都有值。

## 理由

- 枚举每个值只服务一个平台，加平台就加枚举，与“契约不随主题扩张”矛盾；数值槽加平台只加值。
- 退化值让“有 / 无”“圆 / 椭圆”“框 / 下划线”落在同一条画法上，组件代码只写一遍，修一处全主题生效，不再逐主题修 bug。
- 平台数值进了主题，出处可审（0012），组件库不再藏平台知识。

## 不采纳的方案

- **保留枚举、继续加值（如 `handle: pill`）。** 每个平台一个分支，正是要消掉的东西。
- **每个主题一份组件配方。** 等于每套主题写一套组件，违背“一套契约”。
