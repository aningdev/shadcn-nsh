# 0012 派生色是默认值：主题可以带出处覆盖

- 日期：2026-11-25
- 状态：已采纳（2026-11-25）
- 取代：[0007](0007-theme-customization-scope.md) 第 4 条与第 5 条中“只引用的键不许写字面量”的部分；0007 其余各条（全局风格、关键组件、降级、四个控件维度、白名单闸门）照旧

## 背景

0007 第 4 条规定：主题只给约 15 个源色写值，其余 41 个键一律引用源色或套同一条 tint 公式。实施（#388）后，六套主题的生成器算出的官方值有一大半在 `scripts/theme/sources.ts` 的 `reduceColours` 里被覆盖（2026-11-25 用探针在 `main` 上量得，按解析后的颜色比较）：

| 主题                                 | 被改写的派生键（亮 / 暗） | 用户看得见的                                                                                   |
| ------------------------------------ | ------------------------- | ---------------------------------------------------------------------------------------------- |
| nsh-gallery（对照上游 `theme.json`） | 约 20 / 约 25             | 弹层由 #f8f8fb 变白，选中行淡底由 #8cc01d 16% 变成主色 10%，`brand` 由 #4a840a 变成主色        |
| winui                                | 24 / 23                   | 强调色按钮的底边由 #00396e 变成灰 #868686；四档浅填充并成一档                                  |
| material                             | 28 / 27                   | `secondary-foreground`（onSecondaryContainer）、`inverse-brand`（inversePrimary）、`ring` 被改 |
| solid-glass                          | 33 / 33                   | 品牌绿 #00754f 被主色（近黑）取代                                                              |
| shadcn                               | 21 / 23                   | shadcn 官方的 `ring`、`sidebar` 被改                                                           |
| apple                                | 21 / 24                   | 暗色 popover、`input`、`field` 偏一档                                                          |

参照主题（nsh-gallery）因此无法与上游一致，select 弹层在 #388 之后又一次走样；三个平台主题的审计（2026-11-24，ADR 0007 第 2 条的组件）把大部分 A 类问题追到了同一处。

0007 第 4 条的出发点是“派生值不该手写”，这一条没错：大多数主题的大多数派生键确实只是“源色淡一点”。错在把**默认**写成了**强制**：参照规范给了不同的值时，规则选择丢掉规范。

## 决定

1. **键的集合不变。** 主题能写的颜色键仍是 0007 的白名单（源色、引用色、tint、图表、常量），不新增角色；组件读的角色不变。
2. **源色照旧必写。** 0007 第 4 条的 15 个源色每套主题都写值。
3. **派生是默认值。** 引用色、`*-tint`、`chart-*` 默认按 0007 第 4 条派生（引用源色、tint 公式、状态色序列或灰阶）。
4. **主题可以覆盖，但必须有出处。** 参照规范（上游 `nsh-gallery-ui` 的 `theme.json`、平台的官方资源：M3 token、WinUI XAML、Apple 系统色、shadcn 主题）给了与派生不同的值时，主题写那个值，并在该 token 的 `$extensions` 里记下出处（规范名与 token 名，或文件与行号）。没有出处的字面量仍然失败。
5. **tint 的“一个百分比”只约束公式写法。** 用公式的 tint 共用一个 `N`；带出处覆盖的 tint 不受此限。
6. **生成器不再丢值。** 生成器从规范算出的值原样进入主题源码（带出处）；只有规范没给的键才派生。`reduceColours` 只负责补派生、核对源色齐全。
7. **参照主题与上游一致。** nsh-gallery 解析后的颜色与上游 `theme.json` 逐键比较；有意的偏差列在检查的豁免表里，每条写明理由。

## 理由

- **默认值省掉的是“没有理由的手写”，强制省掉的是官方值。** 前者是 0007 想要的，后者是事故的来源。
- **出处让覆盖可审。** 有出处的字面量能被核对（打开规范对一下），没有出处的才是 0007 要拦的“随手写的值”。
- **键集不变，组件与对外槽不受影响。** 这是值的来源规则的修正，不是契约扩充。

## 不采纳的方案

- **扩大源色集合（约 25 个必写）。** shadcn、solid-glass 这类主题本来就是派生的，必写只会让它们手抄一遍派生结果；扩到多少个也没有原则可依。
- **维持 0007 第 4 条，把偏差全记作降级。** 降级是“契约表达不了”的账；这里契约表达得了，是规则自己把值扔了。参照主题也对不上上游，不可接受。
