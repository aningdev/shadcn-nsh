# 0005 跑起来的填充成层，旋钮的选中态成字段

- 日期：2026-11-24
- 状态：已采纳（2026-11-24）
- 规范：[`docs/specs/theme-roles.md`](../specs/theme-roles.md) 第 4、6 节（#363）

## 背景

#363 把 progress、slider、switch 对齐 NSH Gallery 的样子：一段跑起来的填充（进度的条、滑杆的行程、开关打开的轨道）和坐在上面的旋钮。上游为此写了两个 finish：`fill` 与 `knobOn`。第一轮把两者都做成了层（`fill`、`knob-on`），于是 finish 变成 16 个，`FINISH_ROLES_MAX` 也放到 16。

主题契约（`semantics.json` 的 schema）即将冻结。冻结前定下一条：契约必须能完整表达 default（NSH Gallery）主题，其余主题可以降级；**新的层只给一个独立的面，从不给一个状态**。

## 决定

1. **`fill` 保持成层。** 一条跑起来的填充是 `accent`（按钮的面）之外的另一块面：它有自己的底、边与影，占的位置和读者都不同。
2. **删掉 `knob-on`，选中态写成 `knob` 的字段。** 按已有的 `pressed-background` / `pressed-foreground` 写法，`knob` 可写 `checked-background`、`checked-border-color`、`checked-gradient`（读取后是不可枚举的 getter）。只写这几项，因为一个状态只该声明它真正改掉的东西：
   - default：暗色下换白底、选中时平涂（`checked-gradient: "none"`）、换橄榄边；
   - 其余五套：只写 `checked-background`（强调色的字色），影子、边、渐变与没选中时相同。
3. **没写的字段就是没选中时的值。** `checked-*` 不取中性值：选中是同一个面的另一种状态，不声明的那一项自然还是那一项。`checked-gradient: "none"` 是明确的值——选中时平涂，与 `knob` 自己的渐变不同。
4. finish 回到 15 个（12 个层 + 3 种状态），`FINISH_ROLES_MAX` 回到 15。

## 理由

- 层回答“这是屏幕上哪一块面”，状态回答“同一块面此刻是什么样”。`knobOn` 与 `knob` 同形、同位、同影，只是被选中的那个旋钮——它是状态，不是第二块面。
- 状态写成字段，值就落在它所属的那块面旁边：主题作者改旋钮时看一处，组件读一处，`theme:contrast` 也只认一个“不带字的 `knob`”。
- 一个状态若各占一层，每加一个控件状态（按下、选中、拖拽中……）就多一层，且每套主题都要把旋钮的影子和边再抄一遍；冻结后的契约会把这层重复固定下来。
- 反过来说，`fill` 若折进 `accent`，进度的条、滑杆的行程就得和按钮共享按下换色、选中压暗这些只属于强调色按钮的规则，两个面的读者也会混在一起。

## 不采纳的方案

- **`fill` 折回 `accent`。** 跑起来的填充不是按钮的面：它的边与影跟着轨道走，按下与选中也不该由 `accent` 的规则决定。折回去只省一层，却让四套主题的进度条失去自己的橄榄边，也让 `accent` 的读者从按钮扩到进度、滑杆与开关。
- **`knobOn` 继续成层（`knob-on`）。** 把状态当成了面：每套主题要为它重抄 `knob` 的影子和边，两层的值必须始终成套，冻结后还要长期维护一个没有独立面的角色，组件里也多一次二选一。
- **给 `knob` 另写一套完整的选中面（`checked-shadow`、`checked-foreground` 等）。** 没有主题需要它们：选中时影子不变，旋钮上不写字。字段多一个就要多写一次中性值，也会让“一个状态只声明它改掉的东西”失去约束。
