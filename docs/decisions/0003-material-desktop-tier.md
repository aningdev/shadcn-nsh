# 0003 material 的桌面档整体降一步

- 日期：2026-11-24
- 状态：已采纳（2026-11-24）
- 规范：[`docs/specs/theme-contract-v2.md`](../specs/theme-contract-v2.md) 第 12 节 M1（#336，#293 P5b 之后）

## 背景

`material` 的 pointer 档原先按 M3 Density `-2` 推导：高度 24 / 32 / 48dp、图标 16 / 20 / 24dp。但 M3 没有桌面密度规范——Density 是 Compose 给控件加密/放宽的机制，官方只有 touch 与标准两组值，桌面这组数是我们自己减出来的。结果是 `material` 在桌面上比其余主题大一号：`default`、`apple`、`winui` 的指针档都是 24 / 28–32 / 32–40，`material` 是 24 / 32 / 48，同一张设置列表里 `material` 的按钮、大号控件、图标与开关都比旁边大。而 M3 的开关没有密度档（`52×32dp` 是它唯一的尺寸），48 高的控件旁立着 32 高的开关，比例更偏。

## 决定

1. **`material` 的 pointer 档整体降一步**：控制高度 `24 / 32 / 40`（与 `winui` 同档），图标 `12 / 16 / 20`（回到 base 的刻度，pointer 文件因此不再声明 `dimension.icon`）。`touch` 档不动：高度 `32 / 40 / 56`、图标 `16 / 20 / 24`，仍是 M3 的原生 dp。
2. **开关（`bar` 形制）按 M3 的比例缩到 `40×24`**：轨道描边 `1`（未选中）、`0`（选中），钮 `16` → 选中 `20` → 按下 `22`。`52/32 ≈ 40/24`，钮按 `16 → 20` 长、按下再长到 `22`（M3 是 `16 → 24 → 28`），描边取 `1`：M3 的 `2dp` 对一个矮四分之一的轨道是 `1.5`，本库的描边刻度是 `1`，同时给按下的钮留下不越出轨道的余量。`touch` 档仍是 M3 原生 `52×32`、`2/0`、`16 → 24 → 28`。
3. **开关配方改为按档声明**（`Tiered<RecipeShape>`）：M3 既然没给开关密度，桌面上这组数是本库自己的决定，与 M3 的官方值分档并列写出；`winui` 仍是一组（WinUI 3 只发布一个密度）。
4. **pointer 档的 token 描述不再引用 M3 Density `-2`**：写明"比 touch 档低一步、本库自己的桌面尺寸"，并指向本文。

## 理由

- 桌面的一致性优先于"像 M3"：M3 没有桌面值，任何桌面 `material` 都是本库的判断，明说是判断，比伪装成 M3 的密度档更诚实。
- 控件高度、图标、开关三件事一起降，同类控件在五套主题里才同高；只缩开关会留下大一号的表单与图标。
- 开关跟着控件高度走：`40×24` 的开关立在 32 / 40 高的行里比例正常，`52×32` 立在 48 高的控件旁显得孤零零。
- 图标回到 `12 / 16 / 20`：`24` 的图标在 `24` 高的按钮（`height.sm`）里根本塞不下，`20` 与 `40` 高的控件相称，这也是 base 与 `winui` 的刻度。
- 字段（input、select 触发器）的高度是组件常量 `32` / `46`（`fieldSize`），不读高度刻度，因此这一步不需要动它们：它们本来就与 `winui` 同高。
- #336 说"字段 48 → 40"，今天的事实不是这样：单行字段的高度是组件常量 `fieldSize`（`packages/ui/input.tsx`，pointer `32`、touch `46`），五套主题一样，从来不读 `height.lg`。所以"字段 40"没有对应的 token 可改，也没有动它：字段本来就与 `winui` 同高，而让它去读 `height.lg` 会把 `winui` 的字段也抬到 40（WinUI 的 `TextBox` 是 32），那是另一个家族的事。

## 不采纳的方案

- **只把开关缩到 `40×24`，高度与图标留在 24 / 32 / 48 与 16 / 20 / 24。** 设置列表与表单里 `material` 仍比其它主题大一号，开关反而成了列表里最小的东西。
- **按 M3 Density `-4` 再降一档（例如 20 / 28 / 44）。** 低于 24 的可用下限，与其它主题差两档，且比 `-2` 更没有出处。
- **让开关读本库的高度与图标刻度（`height.md`、`icon.md`）。** M3 开关的形态是"轨道比钮高一个钮的份、选中时长到轨道两端"，本库的圆钮刻度（钮 = `icon.md`、轨道 = 钮 + 4）画不出 M3 的比例，等于换掉 `bar` 这个形制。
- **连 `touch` 档一起降。** 触屏是 M3 原生 dp 真正落地的地方，也是这套主题的立足点（48dp 触控目标），没有理由动。
