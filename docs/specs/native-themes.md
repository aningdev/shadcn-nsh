# 原生外观主题：Apple、Material、WinUI 3

本文是方案：目标是**先只用主题数据**，让本库组件分别画出 Apple（Liquid Glass）、Android（Material 3 Expressive）和 Windows（WinUI 3）的外观；同时写清楚主题做不到的部分，以及每一期的验收标准。

它承接 [`positioning.md`](positioning.md) 的差异点 1（多风格 × 主题色），沿用 [`design-semantics.md`](design-semantics.md) 与 [`theme-roles.md`](theme-roles.md) 的规则（基础 token、语义层 `{token}` 引用、形状固定）。调研截止 2026-11。

## 结论

现在的主题只管两样：颜色（`theme.json`）和质感（`semantics.json`）。原生外观还需要另外四类数据：**字体、形状、尺寸密度、动效**，此外还缺一个能接到平台原生材质的出口。

把这五样做成主题数据之后，三套原生外观大约能做到七八成。剩下的部分分两类：

- **组件结构不同**，主题改不了，记在 B 类。
- **NSH 没有对应 API**，要向上游提，记在 C 类。

```
原生外观 = 颜色 + 质感 + 平台材质 + 形状 + 字体 + 尺寸密度 + 动效 + 组件结构 + 系统信号
现在可主题化   ✅      ✅      ❌        ⚠️     ❌       ❌        ❌       ❌        ❌
本方案之后     ✅      ✅      ✅        ✅     ✅       ✅        ✅       部分      ❌（上游）
```

| 平台                     | 只用现有主题 | 做完第 1–3 期 | 剩下的缺口                                                            |
| ------------------------ | ------------ | ------------- | --------------------------------------------------------------------- |
| Apple iOS / macOS 27     | 约 4 成      | 约 8 成       | 跟随系统强调色、透明度滑杆、减少透明度、增强对比度                    |
| Android（M3 Expressive） | 约 3 成      | 约 7 成       | 动态取色、形状变化、Switch 拇指图标、FAB 等组件结构                   |
| Windows 11（WinUI 3）    | 约 5 成      | 约 8 成       | 系统强调色、输入框底部强调线（Mica 是应用的窗口 `backdrop`，见 C 类） |

## 1 三个平台的设计语言

### 1.1 Apple：Liquid Glass（iOS 27 / iPadOS 27 / macOS 27）

| 方面 | 要点                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 材质 | 默认更不透明、背后内容更模糊、玻璃外圈加一道压暗的边、高光更亮、折射更均匀；设置里新增透明度滑杆（从极透到全着色）；遵循"减少透明度"和"增强对比度"；不能再用 `UIDesignRequiresCompatibility` 退出 |
| 形状 | 控件以胶囊形为主；圆角与容器同心（内圆角 = 外圆角 − 间距）；连续曲率（`borderCurve: continuous`）；macOS 27 所有窗口统一成一个更紧的圆角                                                          |
| 结构 | 内容滚到浮动栏下面时，顶部出现统一的工具栏；侧栏铺满窗口边缘；macOS / iPadOS 新增菜单项图标 API（默认隐藏）                                                                                       |
| 字体 | 系统字体 SF Pro；正文 iOS 17pt、macOS 13pt；Dynamic Type                                                                                                                                          |
| 尺寸 | iOS 触控目标 44pt；macOS 控件 24–32pt，行高 28–36（NSH 设计指南）                                                                                                                                 |

- Android：`android={{ ripple }}`；API 31 起支持 `backdropFilter` 模糊。
- 通用：`borderCurve`、系统字体、`fontFamily` 列表、`registerFont`、`fontScale()`、`colorScheme()`、减少动态效果、`platform.os`。

**NSH 没有的**：读系统强调色、动态取色、减少透明度和增强对比度的信号。（Mica 不在其中：它是窗口的 `backdrop`，应用在 `nsh.json` 里设；Android 的模糊与 `borderRadius` 过渡 NSH 都支持，见 C 类。）

## 3 设计

### 3.1 主题仍是两个文件：基础 token 层与跨平台语义层

```
packages/theme/themes/<id>/
  theme.json      基础 token：颜色、3 个层圆角（control / container / modal）及 A 层 radius、字体（NSH setTheme 读取）
  semantics.json  语义层：风格数据 + finishes（shared + 稀疏覆盖）（本库读取）
  index.ts        AppTheme { id, label, theme, semantics }
```

两文件的分层判定规则、`{token}` 引用语法与 DTCG 2025.10 映射见 [`design-semantics.md`](design-semantics.md) 与 [`design-tokens.md`](design-tokens.md)。全部 3 个层圆角（`radius-control`、`radius-container`、`radius-modal`，编译时同时由 `radius-control` 派生 A 层 `radius` 槽）与两个字体族 `font-sans` / `font-mono` 统一定义在 `theme.json`；`semantics.json` 在 Batch 5 统一切换至 Option (b) DTCG 字段命名：`dimension.shape.*` 与 7 个 typography 复合 token 的 `fontFamily` 以 `{token}` 引用基础层，`finishes` 拆为 `shared` 与稀疏 `light`/`dark` 覆写（字段为 `background`、`foreground`、`shadow`、`border-color`、`border-top-color`、`border-bottom-color`，可选的 `gradient`、`backdropFilter`、`material` 与按下换色主题的 `pressed-background` / `pressed-foreground`），按压缩放归入 `state["press-scale"]`。

### 3.2 `semantics.json` 的风格键表

风格数据在 `semantics.json` 顶层、排在 `finishes` 之前，按 DTCG 组别组织（`typography`、`dimension`（含 `shape`/`size`/`stroke`/`focus`/`icon`）、`shape`、`state`、`duration`、`transition`、`motion`、`indicator`），加上 3.3 的 finish `material` 字段：

```jsonc
{
  "typography": {…},
  "dimension": { "shape": {…}, "size": {…}, "stroke": {…}, "focus": {…}, "icon": {…} },
  "shape": {…}, "state": {…}, "duration": {…}, "transition": {…}, "motion": {…}, "indicator": {…},
  "finishes": { "shared": {…}, "light": {…}, "dark": {…} }
}
```

**通用规则**

- **按用途角色命名，不按档位。** 形状和字号写成 `card`、`dialog`、`control`、`body`、`title`…，不写 xs–xl：三个平台的差别是"哪种部件用多大圆角"，不是一把统一的尺子。
- **tier。** 随设备变的值写成 `{ "pointer": …, "touch": … }`：pointer 是桌面（`platform.desktop`），touch 是触屏；模块加载时定，不随窗口变。terminal 的行高和列宽由字符格决定，留在代码里（`surface.tsx` 的 `terminalSizes`），不进主题。
- **默认值不变画面。** default 主题的数就是原来写死在代码里的数；shadcn 与 solid-glass 的风格数与 default 相同，只有 `shape` 的圆角跟它们自己的 `theme.json` 走（见下）。
- **形状固定。** 六套主题 7 组的键集合完全相同、叶子的类型相同、枚举取白名单里的值、`shape` 与 `theme.json` 的圆角一致：`bun run check:theme` 逐项检查，缺一个键就点名（`scripts/theme/style.ts`）。
- **读取。** `style()` 给出当前主题的风格（响应式：读它的地方在 JSX、`draw`、effect 里随 `selectTheme` 下一帧重画）。`density`、`controlSize`、`motion`、`cornerCurve`、`focusRing` 保持原来的对象形状，每个键是一个 getter，读 `style()`。`density` 的 `title` / `note` / `body` 取 `typography.title` / `typography.detail` / `typography.body` 的 `fontSize`，`controlSize` 的 `label` / `detail` 取 `typography.label` / `typography.detail`，所以字号只写一处。
- **曲线名称映射。** 只写曲线的名字（`transition.enter.timingFunction` 与 `motion.*.timingFunction`），名字到曲线的映射在 `theme.ts`，白名单在 `style.ts`。
- **表里的数。** "default" 一列读自现在的代码；apple / material / winui 三列来自各平台公开规范的概要，标"约"的是近似值，"待核对"的要在第 3 期回官方 token 文件逐项核对后写回本节；"—" 是该平台没有这个概念，取 default 的值。

#### typography：7 个角色

每个角色是 `{ fontSize, lineHeight, fontWeight, letterSpacing }`：`fontSize` 和 `lineHeight`（整数点数）分 pointer / touch，`fontWeight` 是数字 `400`–`700`，`letterSpacing` 是字距（点）。SF 和 Material 都按字号调字距，所以 `letterSpacing` 不能省。DTCG 的 `lineHeight` 是**字号的无单位倍率**，所以源码里存倍率：生成器写整数点数，`dtcg.ts` 除以字号写进 `font.line-height`，`tokens:build` 再乘回点数写进 `semantics.json`（`font.lineHeight(role)` 直接返回点数）。7 个复合 token 的 `fontFamily` 一律 `{font.family.sans}`；正文家族由 NSH 自己画，本库不读 `font-sans`。字号乘以 NSH 的 `fontScale()`，跟随系统字号设置（第 1b 期）。

| 高度 | `dimension.size.height.{sm,md,lg}`           | `controlHeight.sm/md/lg`（按钮）与 `controlSize.row` / `.line` / `.tabs`（都取 `lg`） |
| 图标 | `dimension.icon.{sm,md,lg}`                  | `iconSize.sm/md/lg`，以及 `controlSize.check`（`sm`）与 `.control` / `.clear`（`md`） |
| 间距 | `density.{pad,gap}`、`control.{padding,gap}` | `density.pad/gap`、`controlSize.padding/gap`                                          |

`dimension.size.hit`、`density.surface`（区块面的圆角）与 `control.dot` 不进这三把尺子，各管一件事。`check:theme` 的 `checkScales` 要求高度与图标逐档递增、都是 4 的整数倍，间距取自 `4, 8, 12, 16, 24, 32` 且每档最多三个值 —— 平台自己的例外值在 [`theme-roles.md`](theme-roles.md) §2b 的表里点名（目前只有 WinUI 的 6 点按钮内边距）。

`density` 和 `control` 的 pointer / touch 两档就是原来的 `density` 与 `controlSize`；它们的 `label`、`detail`、`title`、`note`、`body` 已改读 `type`。Apple 的数（第 2b 期）取自 HIG 的 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 与 [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：触摸目标最小 44 点，macOS 的标准控件高约 28 点（small 24、large 32），iOS 按钮 44 点（大号 56）；`density.surface` 取与 `shape.container` 相邻的同心一档（pointer 12、touch 20）。Material 的数（第 3 期）已核对：无独立桌面数值的 pointer 密度按 M3 Density `-2` 档推导，其余取 Compose / Material Web tokens，高度三档就是 `ButtonXSmall` / `ButtonSmall` / `ButtonMedium` 的 32 / 40 / 56。WinUI 3 的数（第 3 期）已核对：WinUI 3 仅发布标准桌面密度，touch 档高度按本库约定取 pointer + 8（`TabView` / `ComboBox` / `ListViewItem`）。default 的 32 点（原来是 34）与 touch 的 32 点（原来是 36）是为落在 4 的格子上取的最近一档。

### 3.3 平台材质：finish 的 `material` 与 `elevation`

```jsonc
"overlay": {
  "background": "oklch(from {popover} l c h / 0.85)",
  "shadow": "…",
  "border-color": "{glass-edge}",
  "backdropFilter": "blur(30px)",   // 平台不画材质时的回落，所有平台都用得上
  "$extensions": { "dev.aning.shadcn-nsh": { "material": "acrylic" } }
},
"card": {
  "background": "{card}",
  "$extensions": { "dev.aning.shadcn-nsh": { "material": "none", "elevation": 1 } }
}
```

- `material` 是枚举 `"none" | "glass" | "acrylic"`，只说"这个面要哪种平台材质"，不写平台对象的形状；所有主题、所有 finish 都写，不要材质的写 `"none"`（编译后是 `null`，与平涂不写 `gradient` 同一处理）。
- 配方只有一份，在 `packages/theme/materials.ts`：`glass` 要系统玻璃（`glassEffect: "regular"` 与 `ios.backdropMaterial`），`acrylic` 要宿主窗口的模糊（`windows.backdrop: "blur"`）。每个配方另带回落：模糊半径与面色的最低不透明度，平台不画材质时 `backdropFilter` 兜住（`check:theme` 核对面色的 alpha 不低于它）。
- `themed()` 读 finish 时，要玻璃的面把配方的 `glassEffect` 放进 style，`glassTintColor` 是该面自己的 `background`（色值走 alias 路径，不写字面量）；`material` 本身从不进 style。`ios`、`windows` 不是 style 键，由 `theme.ts` 的 `platformMaterial(role)` 按配方返回；`elevation` 是 Android 自己的阴影高度（dp），在同一处作为 `android.elevation` 给出。组件在同一个 View 上 `{...platformMaterial("overlay")}` 铺开。`material` 为 `null` 时 style 的键与以前完全一样。
- 用 finish 的组件需要多铺开一组 props。`nsh/base` 的弹层（`Menu`、`Select`、`Popover` 的 popup）只开放 `popupStyle`，所以那里只有 style 里的玻璃键生效，`ios` / `windows` 铺不上去；这是已知限制，要用就在应用自己的 View 上铺。
- 各主题的分配：`apple` 的 `overlay`、`inverse`、`raised`、`glass` 用 `glass`；`winui` 的 `overlay` 用 `acrylic`；其余全部 `"none"`。`material` 的层级只用 `elevation`（`card`/`raised`/`hover`/`pressed` 1、`overlay`/`glass` 3、`modal`/`inverse` 6）。
- 记下没做的部分（不是待办，是取舍）：Acrylic 的颗粒（`sc_noiseOpacity` 0.02）、luminosity 混合与 1.25 饱和度；Mica、macOS 的 `behindWindow` 与侧栏 vibrancy（窗口层，属于应用的事）；CSS 的折射。`macos.backdrop` 也不写：显式写它会盖过 macOS 26 上的 `glassEffect`（见 `references/nsh/docs/dev/macos.md`），26 以下由模糊回落兜住。

### 3.4 按平台自动选主题

- 新增 `themes/native/index.ts`，导出 `nativeTheme()`，按 `platform.os` 返回 `apple`（iOS / macOS）、`material`（Android）或 `winui`（Windows），按 NSH 兼容性规定，`switch` 写 `default` 分支，其余平台回落到 default 主题。
- 不新增 `selectTheme("auto")` 这种别名，应用自己调用 `selectTheme(nativeTheme())`。
- `init` 的风格选择里加一项 "Native (per platform)"，等于同时复制四套主题（apple / material / winui / default）和 `native/index.ts`。

- ✅ 字段指示器与圆角：共用逻辑在 `lib/indicator`（`fieldPresets`、`fieldIndicator`、`fieldCorners`、`fieldCornerClass`、`fieldEdgeWidths`、`fieldEdgeClass`、`fieldRestEdge`、`fieldFocusClass`、`fieldFocusEdge`），`Input`、`Textarea`、`InputGroup`、`Select`、`DatePicker`、`Combobox`、`CodeEditor`、`NumberInput`、`TimeField` 与 OTP 的格子都读它。`indicator` 三值：`box` 是 `stroke.control` 的方框（`input` 色），聚焦时方框连同光环一起变成强调色；`underline` 只画下边线（静止时 `muted-foreground`，聚焦时 `focus.width` 的强调色，不画光环）；`box-underline` 是 `border` 色的方框、下边为 `input` 色（WinUI `TextBox`：三边 `ControlStrokeColorDefault`，底边 `ControlStrongStrokeColorDefault`），悬停时不变，聚焦时只有下边线变成 `focus.width` 的强调色（无效时 `destructive`），方框保持本色、不画光环（WinUI `TextBox`）。`top` 只圆上两角。终端里的字段一律按 `box` 画（`border` 加光环），与之前相同。
- ✅ 颜色 token `inverse`、`inverse-foreground`、`inverse-brand`；finish `dialog`、`tooltip`、`inverse`。读取方：`DialogContent`、`Tooltip`、`Toast`、`Bubble` 的淡底变体（后者的字读 `accent-foreground`）。`AlertDialog` 不画卡片，没有读取方。
