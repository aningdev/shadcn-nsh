# 定位与路线

## 定位

**NSH 的 shadcn：一套组件，多种风格；手机与桌面自适应；随 NSH 同日更新；复制进来就是你的代码。**

组件由本库自己抽取并拥有：上游示例 `nsh-gallery-ui` 与官方推荐的样子是参考规范，不是照搬的源头。差异要建在上游与 shadcn 都不做、也不适合做的事情上。

## 局面

| 选项                  | 是什么                       | 缺什么                             |
| --------------------- | ---------------------------- | ---------------------------------- |
| 上游 `nsh-gallery-ui` | 官方示例的外观代码           | 不可安装、一种外观、API 偏演示     |
| `nsh/base`            | 行为与无障碍，无样式         | 外观要从零写                       |
| shadcn                | 生态最好                     | 只支持 Web DOM，NSH 原生渲染用不了 |
| 本库                  | 可安装、复制即拥有、文档测试 | 一种外观、API 不统一、没有组合层   |

## 已有资产

- **跟上游**：`port:vendor` + `port-map` 自动搬运、漂移检测、像素门禁、原生行为测试；NSH 发版当天即可适配。
- **分发**：CLI `init / add / list / view / diff`，复制即用的安装测试覆盖每个条目。
- **外观是数据**：`theme.json` 的颜色 token 与 `finishes.json` 的质感角色，组件只按角色读取。
- **自适应经验**：Phone / Desktop 画布、idiom、`Split`。

## 差异点（按优先级）

1. **多风格 × 主题色**：`init` 时选风格（上游立体 / 平面 …，即 `finishes` 一层）与颜色（`theme.json` 一层）；文档站在线切换与调色。前提：风格只换数据即可成立（`theme-shadcn` 实验验证）。
2. **原生应用 Blocks**：不照搬网页 blocks，做原生应用才有的场景：AI 对话、桌面工作区（dock、菜单、快捷键）、手机设置与 sheet 流程、编辑器。每个都手机 / 桌面自适应。Block 只组合现有组件与主题角色，不写颜色、不自创外观。
3. **统一、shadcn 式的 API**：`variant` / `size` / `tone` 统一命名，贴近 shadcn；复制后的代码好读好改。只改外壳，不动 `// @port` 区域。
4. **模板脚手架**：几套开箱即跑的壳应用（如 AI 对话、桌面工作区、手机标签页应用），`shadcn-nsh create <name> --template <id>`：底层是 `nsh init` + `shadcn-nsh init` + 一组 Blocks，选好的风格与主题色一并写入。
5. **随 NSH 同日更新**：公开兼容矩阵（本库版本 ↔ NSH 版本）。
6. **面向 AI 编程助手**：`llms.txt` 之外，提供 registry 的 MCP / 说明，让编程助手能直接 `add` 并正确使用。

**不做**：把 `lib` 做成独立 npm 包（违背复制即拥有）；改 `nsh` / `nsh/base`。外观归本库，上游的变化由 `port:check` 提醒、审阅后采纳（第 5 条说的"同日更新"指 NSH 运行时与 `nsh/base` 的兼容，与示例外观的同步无关）。

## 路线

| 阶段        | 内容                                                                                                              | 产出                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 0（进行中） | 主题实验：平面风格能否只换数据                                                                                    | `docs/specs/theme-shadcn.md` 与对比截图 |
| 1 打地基    | 统一 API（破坏性，一次做完）；`registry:build` 把维护者文件头换成给用户看的说明；`icons` 按图标拆分减轻安装重量   | CLI / registry 0.3.0                    |
| 2 做差异    | 多风格 / 主题（registry 形态、`init` 选择、文档站切换与调色）；Blocks（AI 对话 → 桌面工作区 → 手机设置 → 编辑器） | 风格与 Blocks 页面                      |
| 3 做生态    | 模板脚手架 `create`；兼容矩阵；AI 助手接入；展示站首页                                                            | 模板与展示                              |

阶段 1 在前：用户变多之后再改 API 代价更大。阶段 2 的两条可并行。

## 现状评估（2026-11-14，进入阶段 1 的依据）

| 层面     | 评价 | 依据                                                                                                                                                                                                            |
| -------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主题层   | 强   | 颜色 55 个 token、质感 19 个角色、圆角，全是数据                                                                                                                                                                |
| 单实例   | 中上 | Props 继承 `nsh/base`，`class` / `style` 透传                                                                                                                                                                   |
| 复制后改 | 中   | 约 46% 是上游写法的外观函数；一个组件连同依赖安装的中位数约 1700 行；`icons.tsx` 814 行被 16 个组件依赖                                                                                                         |
| 一致性   | 偏弱 | 变体命名不一（`ButtonKind`、`"ghost" \| "secondary"`、`"ring" \| "tile"`、`kind`）；`tone` 四种写法；`size` 有命名、数字、`Live<>`；54 个 registry 文件把维护者说明（`port:vendor`、`port-map.json`）发给了用户 |
