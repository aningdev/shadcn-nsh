# 定位与路线

文档站：<https://shadcn-nsh.aning.dev/>

## 定位

**NSH 的 shadcn：一套组件，多种风格；手机与桌面自适应；随 NSH 同日更新；复制进来就是你的代码。**

组件由本库自己抽取并拥有：上游示例 `nsh-gallery-ui` 与官方推荐的样子是参考规范，不是照搬的源头。差异要建在上游与 shadcn 都不做、也不适合做的事情上。

## 局面

| 选项                  | 是什么                       | 缺什么                                                       |
| --------------------- | ---------------------------- | ------------------------------------------------------------ |
| 上游 `nsh-gallery-ui` | 官方示例的外观代码           | 不可安装、一种外观、API 偏演示                               |
| `nsh/base`            | 行为与无障碍，无样式         | 外观要从零写                                                 |
| shadcn                | 生态最好                     | 只支持 Web DOM，NSH 原生渲染用不了                           |
| 本库                  | 可安装、复制即拥有、文档测试 | 组合层与模板还没铺开：没有 Blocks、模板脚手架，`create` 未做 |

## 已有资产

- **跟上游**：`port:vendor` + `port-map.json` 管住来源与去向，`port:check` 提醒上游变化（审阅后采纳，`port:review`），`port:render` 做像素门禁，`test:install` 逐条目在真实应用里装一遍；NSH 发版当天即可适配。
- **分发**：CLI `init / add / list / view / diff`，registry 随版本发布（`v<version>/public/r`），装到的文件与在跑的 CLI 对得上。
- **外观是数据**：`theme.json` 的 token 与 `finishes.json` 的 finish，组件只按 token 与 finish 读取；三套主题数据（本库默认、shadcn、solid-glass），运行时可切换（`selectTheme`），文档站的演示也能换着画。
- **API 一致**：`variant` / `size` / `tone` 统一，部件名照 shadcn（`Trigger` / `Content` / `Item` …），词表由测试固定。
- **自适应经验**：Phone / Desktop 画布、idiom、`Split`、终端形态。

## 差异点（按优先级）

1. **多风格 × 主题色**：`init` 时选风格（`finishes` 一层）与颜色（`theme.json` 一层）；文档站在线切换已可，在线调色未做。原生外观（Apple / Material / Fluent）的方案见 [`native-themes.md`](native-themes.md)。
2. **原生应用 Blocks**：不照搬网页 blocks，做原生应用才有的场景：AI 对话、桌面工作区（dock、菜单、快捷键）、手机设置与 sheet 流程、编辑器。每个都手机 / 桌面自适应。Block 只组合现有组件与主题的 token、finish，不写颜色、不自创外观。
3. **统一、shadcn 式的 API**：`variant` / `size` / `tone` 统一命名，贴近 shadcn；复制后的代码好读好改。外壳与 `// @port` 区域都归本库，都可以改；上游同一处的后续变化变成 `port:check` 的待审阅项，不再是"不一致"。
4. **模板脚手架**：几套开箱即跑的壳应用（如 AI 对话、桌面工作区、手机标签页应用），`shadcn-nsh create <name> --template <id>`：底层是 `nsh init` + `shadcn-nsh init` + 一组 Blocks，选好的风格与主题色一并写入。
5. **随 NSH 同日更新**：公开兼容矩阵（本库版本 ↔ NSH 版本）。
6. **面向 AI 编程助手**：`llms.txt` 已发布（文档站根），下一步是 registry 的 MCP / 说明，让编程助手能直接 `add` 并正确使用。

**不做**：把 `lib` 做成独立 npm 包（违背复制即拥有）；改 `nsh` / `nsh/base`。外观归本库，上游的变化由 `port:check` 提醒、审阅后采纳（第 5 条说的"同日更新"指 NSH 运行时与 `nsh/base` 的兼容，与示例外观的同步无关）。

## 路线

| 阶段       | 内容                                                                                                               | 状态                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 0 主题实验 | 平面风格能否只换数据：换一套主题数据，组件照常渲染                                                                 | 完成。`theme-shadcn` 已作为主题条目发布，实验记录在 [`theme-shadcn.md`](../archive/theme-shadcn.md) |
| 1 打地基   | 统一 API（破坏性，一次做完）；registry 文件头给用户看；`icons` 改为直接引入 `lucide`                               | 完成，随 `0.3.0`                                                                                    |
| 2 做差异   | 多风格 / 主题（主题条目、`init` 选择、运行时切换、文档站切换）；Blocks（AI 对话 → 桌面工作区 → 手机设置 → 编辑器） | 进行中：主题一半已完成（`0.5.0` 运行时切换、solid-glass 主题、文档站可切换）；在线调色、Blocks 未做 |
| 3 做生态   | 模板脚手架 `create`；兼容矩阵；AI 助手接入；展示站首页                                                             | 未开始。兼容矩阵的一行已在 README，`llms.txt` 已发布；`create` 与 MCP 未做                          |

阶段 1 已在前：用户变多之后再改 API 代价更大。阶段 2 的两条可并行。

## 现状

| 层面     | 评价 | 依据                                                                                                                                                      |
| -------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主题层   | 强   | 颜色 token、finish、圆角全是数据，三套主题；运行时切换后已渲染的组件下一帧跟着变                                                                          |

| 一致性   | 中上 | `variant` / `size` / `tone` 已统一，部件名照 shadcn，词表由 `api-vocabulary.test.ts` 固定；`tone` 与各组件轴的第二轮统一见 [`api-unify.md`](api-unify.md) |
| 组合层   | 中   | `card` / `field` / `item` / `sidebar` / `navigation-menu` / `message` 系列等组合组件已就位；Blocks 与模板还没有                                           |
